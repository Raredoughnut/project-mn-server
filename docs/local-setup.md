# 프론트엔드 로컬 개발 환경

백엔드를 로컬에 띄우고 **실제 데이터**로 화면을 만들 수 있게 하는 문서다.
API 스펙은 [docs/api.md](api.md)에 따로 있다.

환경변수는 하나도 설정할 필요가 없다. 기본값이 전부 로컬에 맞춰져 있다 —
백엔드는 `localhost:8080`, 프론트는 `localhost:3000`을 가정한다.

---

## 1. 준비물

| | 비고 |
|---|---|
| Docker | PostgreSQL 컨테이너용 (`compose.yaml`) |
| JDK 17 이상 | `./gradlew` 실행용. 컴파일에 쓰는 Java 25는 Gradle이 알아서 받는다 |
| 구글 OAuth 자격증명 | **저장소에 없다. 백엔드 담당자에게 직접 받을 것** |

리디렉션 URI(`http://localhost:8080/login/oauth2/code/google`)는 이미 등록돼 있어서,
받은 자격증명을 그대로 쓰면 로그인이 된다.

## 2. 실행

```bash
docker compose up -d          # PostgreSQL. DB/유저/비번 모두 mnarchive

export GOOGLE_CLIENT_ID=...
export GOOGLE_CLIENT_SECRET=...

./gradlew bootRun             # Flyway가 스키마를 자동 적용한다
```

마이그레이션은 따로 실행할 게 없다. 기동할 때 Flyway가 `V1` → `V2` → `V3`를 순서대로 적용한다.

띄운 뒤 <http://localhost:8080/swagger-ui.html> 에서 엔드포인트를 직접 호출해 볼 수 있다.

## 3. 데이터 채우기

기동 직후 DB는 **비어 있다.** 곡·보면·점수는 전부 임포트로 생긴다. 두 가지 방법이 있다.

### 방법 A — 직접 임포트 (권장)

팝픈을 한다면 이게 가장 낫다. 자기 실제 점수와 프로필이 들어가서 모든 화면이 실데이터로 동작한다.

1. `http://localhost:8080/oauth2/authorization/google` 로 로그인
2. `POST /api/me/bookmarklet` 호출 → 응답의 `bookmarklet` 문자열을 즐겨찾기로 저장
   (Swagger UI의 Try it out으로도 된다)
3. e-amusement 팝픈 플레이 데이터 페이지에서 그 즐겨찾기를 클릭
4. 우측 하단 진행률 오버레이가 끝나면 완료

곡 목록은 80페이지 정도를 훑으므로 1분쯤 걸린다.

### 방법 B — DB 덤프 받기

팝픈을 안 하거나 임포트 전에 화면부터 보고 싶을 때. 백엔드 담당자에게 덤프를 받아서:

```bash
psql -h localhost -U mnarchive -d mnarchive -f mnarchive-dev-dump.sql
```

곡 940개와 보면 1064개가 들어온다. 단 **점수는 덤프를 만든 사람의 계정에 묶여 있어서**,
본인 구글 계정으로 로그인하면 새 사용자가 되어 점수 칸은 비어 있다.
곡 목록 UI("아직 안 친 곡" 상태)는 만들 수 있고, 랭킹은 비어 있다.

## 4. 화면별로 데이터가 언제 생기는가

| 화면 | 필요한 것 |
|---|---|
| 로그인 / `GET /api/me` | 로그인만 하면 된다 |
| 곡 목록 `GET /api/songs` | 임포트 또는 덤프 |
| 점수가 채워진 곡 목록 | **본인 계정으로 임포트** |
| 랭킹 `GET /api/rankings/players` | 임포트 + `PUT /api/me/ranking-visibility`로 공개 켜기 |

랭킹은 **공개에 동의한 사용자만** 나오고 기본값이 꺼짐이다.
초기에 비어 있는 게 정상이므로 빈 상태 화면을 준비할 것.

## 5. 확인 부탁드리는 것 두 가지

브라우저에서만 확인 가능한 부분이 남아 있다. 첫 임포트 때 **개발자 도구 콘솔을 열어두고**
아래 두 가지를 봐주면 크게 도움이 된다.

### (1) 북마클릿이 로컬 백엔드로 전송되는가

이게이트는 HTTPS인데 로컬 백엔드는 `http://localhost:8080`이다. Chrome의
Private Network Access 정책이 공개 사이트 → 로컬호스트 요청을 막을 가능성이 있다.

- **정상이면**: 오버레이에 "완료! N개 갱신"
- **막히면**: "실패: Failed to fetch" + 콘솔에 private network 관련 경고

막히면 알려달라. 로컬 HTTPS를 붙이는 방식으로 우회한다.

### (2) 프로필 라벨이 맞는가

팝클래스·플레이 횟수를 읽는 파서의 **일본어 라벨이 아직 실검증되지 않았다.**
프로필 페이지에서 콘솔에:

```js
__popnParseProfile(document)
```

라벨 원문, 파싱 결과, 못 찾은 라벨 목록이 출력된다. 결과를 그대로 공유해주면 된다.
(북마클릿을 한 번 실행해 스크립트가 로드된 상태여야 이 함수가 있다.)

프로필 파싱이 실패해도 스코어 수집은 계속되니, 안 되더라도 다른 작업에 지장은 없다.

## 6. 잘 안 될 때

| 증상 | 원인 |
|---|---|
| 모든 요청이 401 | `credentials: 'include'` 누락. [api.md](api.md#인증) 참고 |
| 쓰기 요청만 403 | CSRF 토큰 누락. [api.md](api.md#csrf) 참고 |
| 콘솔에 CORS 오류 | 대개 진짜 원인은 인증이다. 위 두 가지를 먼저 확인할 것 |
| 곡 목록이 빈 배열 | 아직 임포트하지 않았다 |
| 랭킹이 빈 배열 | 공개 설정이 꺼져 있거나, 임포트 전이다 |
| 북마클릿 "Failed to fetch" | 위 5-(1) 참고 |
| 기동 시 `ddl-auto: validate` 실패 | 엔티티와 스키마 불일치. 백엔드 담당자에게 알릴 것 |

## 7. 알아둘 것

- **`./gradlew test`는 로컬 개발 DB에 Flyway를 실행한다.** 테스트가 `@ActiveProfiles("test")`인데
  해당 설정 파일이 없어 기본 설정으로 붙는다. 추가 전용 마이그레이션이라 데이터는 안전하지만,
  알고 있는 편이 좋다. (CI를 붙일 때 정리 예정)
- 북마클릿을 **재발급하면 이전 것이 즉시 무효가 된다.** 여러 브라우저에 설치했다면 나머지가 끊긴다.
- `charts.level`, `songs.version/bpm/duration`은 아직 시딩 전이라 **전부 `null`**이다.
  난이도별 정렬·필터 UI는 이 값이 채워져야 만들 수 있다.
